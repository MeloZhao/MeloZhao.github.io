CyclDesign：把蛋白质环化设计做成一条流水线

环化设计的难点从来不是某一步做不出来，而是每一步都做出来了，但拼不起来。

结构预测给你一个 pLDDT 0.9 的模型，ProteinMPNN 给你 100 条序列，Rosetta 给你一堆 ddG——然后呢？哪一条该拿去做实验？

CyclDesign 想解决的就是这个「然后」。

设计目标

一条环化候选要同时满足四件事：

  1. 几何上闭得上 —— 首尾距离、linker 长度、无严重 clashes；
  2. 序列上表达得出来 —— 没有极端疏水 patch，没有罕见密码子偏好问题；
  3. 能量上稳定 —— 环化前后 ΔΔG 合理，不是靠 strained 构象硬撑；
  4. 动力学上不散 —— 200 ns 里 RMSD 收敛，活性位点几何保持。

这四条对应四个独立的筛选层。任何一层没过，就不该进入下一层——不然你会在最后一层发现前面全白做了。

流水线结构

text
PDB / FASTA
    │
    ├─ 01 环化可行性评估      (首尾 Cα 距离 / 柔性)
    ├─ 02 组合生成            (linker 长度 × 类型 × 位点)
    ├─ 03 结构预测            (AlphaFold / RF3)
    ├─ 04 几何筛选            (RMSD / clash / 二级结构)
    ├─ 05 序列重设计          (ProteinMPNN)
    ├─ 06 能量打分            (Rosetta / FoldX)
    └─ 07 候选优选            (多目标排序)

每一层都往磁盘写自己的结果，下一层只读上一层的清单。这意味着任何一层改了参数，只需要从那一层重跑，不用从头再来。

为什么不用一个大脚本

我一开始真的写了一个 800 行的 run_all.py。三个月后它变成了这样：

  • 想换 linker 长度，要改第 214 行的常量；
  • 想跳过结构预测复用已有模型，要注释掉第 300–380 行；
  • 想并行跑 20 个骨架，发现中间文件全写在同一个目录里，互相覆盖。

后来换成了 Snakemake。核心规则大概是这样：

python
rule predict_structure:
    input:
        "02_design/{design_id}.fasta"
    output:
        "03_struct/{design_id}.pdb"
    params:
        model=config["af_model"]
    shell:
        "python scripts/predict.py --in {input} --out {output} "
        "--model {params.model}"

好处不是「优雅」，而是可恢复。跑到第 47 个设计时集群挂了，重跑只补缺的那些。

几何筛选的判据

这一层最容易被写成「看起来还行」。我最后定下来的硬阈值：

指标阈值理由
首尾 Cα 距离3.5–6.0 Å太短会 strain，太长 linker 兜不住
linker 内 clashes0一个都不行
环化后 RMSD（vs 线性）< 2.5 Å保持整体折叠
二级结构破坏不允许螺旋/折叠被 linker 打断就废了
末端 B-factor< 60太柔的末端闭上也留不住

这些数字不是文献抄来的，是在自己的体系上试出来的。换体系一定要重新标定——这点我觉得比阈值本身更重要。

多目标排序

到了第 7 层，你手上可能有几十条「都还行」的候选。单看任何一项指标都会选出偏科的东西。

我用的是最简单的做法：每个指标转成百分位排名，然后加权求和。

python
score = (
    0.30 * pct(stability_ddg) +
    0.25 * pct(shape_complementarity) +
    0.20 * pct(expression_score) +
    0.15 * pct(rmsd_to_linear) +
    0.10 * pct(linker_confidence)
)

权重可以改，但必须写下来。不然三个月后你会忘了为什么第 3 条排在前面。

排序的作用不是选出唯一正确答案，而是把「值得做实验的 5 条」从「看起来都不错的 40 条」里挑出来。

现在的状态

流水线能跑通，但还缺两块：

  • 负样本。现在所有筛选都是「挑好的」，没有「主动排除坏的」的模型。没有负样本，阈值就只能靠拍脑袋。
  • 实验闭环。目前只有计算结果，没有表达量、没有活性数据。没有这一环，权重永远是猜的。

下一步是把前两批候选送出去做表达，拿回来的数据反哺排序权重。
